# CLAUDE.md

Unity 6.3 (6000.3.26f1, URP) test environment for training the URDF-imported **delivery_bot** with ML-Agents.
README.md covers usage; this file records what was changed in the project and the non-obvious parts to know before
changing anything. It is a test environment, not the final version.

## Changes made to the project (19 Oct 2026)

Starting point: the empty URP template ("Initial check-in").

1. **Packages** (`Packages/manifest.json`)
   - Added `com.unity.ml-agents` 4.0.3 (pulls in `com.unity.ai.inference` 2.6.1) and
     `com.unity.robotics.urdf-importer` from git `#v0.5.2`. `com.unity.ai.assistant` is installed and provides the
     Unity MCP bridge.
   - Pinned the template packages to the versions Unity 6.3 resolves (Input System 1.20.0, URP 17.3.0,
     Test Framework 1.6.0, …). An earlier session had left the old template minimums in the manifest, and
     Input System 1.12.0 fails to compile on 6.3 (`BuildTarget.ReservedCFE`).
   - Removed `Assets/Editor/HubForceResolve.cs`, a one-off Hub script.
2. **Project settings**
   - Physics: fixed timestep 0.01 s (100 Hz), solver iterations 12/4, `Robot` layer does not collide with itself.
   - Tags `Obstacle`, `Wall` and layer `Robot` (8) added. The tag `robot` comes from the URDF Importer.
   - Player: Run In Background on. Version Control mode: Visible Meta Files (it had been switched to Unity Version
     Control).
   - The training scene is first in the Build Settings.
3. **Code** (`Assets/DeliveryBot/`, namespace `DeliveryBot`)
   - `Scripts/DeliveryBotDrive.cs`: finds the joints by `UrdfJoint.jointName`, configures the ArticulationBody
     drives from the URDF README values, and turns (speed, steering angle) into Ackermann steering angles and
     per-wheel velocities. Measures wheelbase, track width and wheel radius at start-up. `ResetPose()` teleports the
     root and zeros the joint states.
   - `Scripts/DeliveryBotAgent.cs`: ML-Agents `Agent`. 10 vector observations, 2 continuous actions, rewards,
     episode end conditions, mass/torque randomisation, keyboard heuristic (Input System).
   - `Scripts/TrainingArena.cs`: 20×20 m arena, pooled obstacles, spawn/goal placement. Reads the environment
     parameters `goal_distance` and `obstacle_count` (curriculum).
   - `Scripts/SensorPoseRandomizer.cs`, `Scripts/LinkCollisionReporter.cs`: helpers.
   - `Editor/DeliveryBotSetupWindow.cs`: **Tools > Delivery Bot > Setup**. Applies the project settings, creates the
     scene, imports and configures the URDF, saves the prefabs, lays out arena copies.
4. **Content**
   - `Assets/URDF/delivery_bot/`: URDF package V-0.2 (from Fusion, see its README). `meshes/*.asset|*.prefab` and
     `Assets/URDF/Materials`, `Assets/URDF/meshes` are generated by the importer and referenced by the prefabs.
   - `Assets/DeliveryBot/Scenes/DeliveryBotTraining.unity`: one arena with the configured robot.
     `Prefabs/DeliveryBot.prefab` and `Prefabs/TrainingArena.prefab` are written by the setup window.
5. **Python** (`.venv`, Python 3.10.12, created with `uv`; there is no pip in it, use `uv pip`)
   - `mlagents` 1.1.0, `grpcio` 1.62.3 (override), `torch` 2.2.2, `setuptools<75`. See `requirements-training.txt`.
   - `config/delivery_bot_ppo.yaml`: PPO, behavior `DeliveryBot`, curriculum.
6. **.gitignore**: `.venv/`, `results/`, `Assets/ML-Agents/` (timer dumps), `Assets/URDF/*.import.urdf`,
   `.DS_Store`, Python caches.

## Gotchas

- **URDF package root:** the importer resolves `package://delivery_bot/...` relative to the folder that contains the
  `.urdf`. `DeliveryBotSetupWindow.PrepareUrdfForImport` therefore writes `Assets/URDF/delivery_bot.import.urdf`
  next to the package folder and imports that copy (git-ignored). Don't move the URDF out of `delivery_bot/urdf/`
  without checking this.
- **Frame-only links** (sensor and optical frames) have no `<inertial>`, so Unity would give each one 1 kg. The
  setup window sets them to 0.01 kg. Mass randomisation skips bodies under 0.05 kg.
- **Sensors sit on child "mount" objects** (`LidarSensor`, `RadarSensor`, `CameraSensor`) under the links. The links
  are ArticulationBodies, so their transforms can't be jittered at runtime.
- **The importer's `Controller` component** (keyboard joint control) overrides the drive settings in `Start()`. The
  setup window removes it; keep it removed.
- **Joint signs:** the importer maps the URDF axes so that the URDF sign conventions hold (positive steering = left,
  positive wheel velocity = forward). Verified in Play mode: a 15° command gave a 1.91 m turning radius against a
  predicted 1.87 m. `invertSteering`/`invertWheels` exist only as a fallback.
- **Python pins:** `torch` > 2.2 makes `torch.onnx.export` need `onnxscript`, so the ONNX export at the end of
  training crashes. `mlagents` imports `pkg_resources`, which `setuptools` ≥ 81 removed. `grpcio` 1.48.2 has no
  macOS arm64 wheel.
- **Re-running "Configure"** unpacks the arena prefab instance before re-saving the robot prefab. Unity can't save a
  nested part of a prefab instance as its own prefab.
- `BehaviorParameters.VectorObservationSize` must match `DeliveryBotAgent.VectorObservationSize`. If you change the
  observations, change both and re-run Configure, and don't resume runs trained with the old size.

## Working with the Unity MCP tools

- Check compile errors with `Unity_GetConsoleLogs` after editing scripts. The MCP connection drops for about 10 s
  during each domain reload (after a refresh and on entering/leaving Play).
- `Unity_RunCommand` can't do anything that opens a dialog. Delete assets from the shell, then `AssetDatabase.Refresh()`.
- The editor doesn't advance Play mode while Unity is not the focused app (`Time.frameCount` stays put). Bring Unity
  to the front for Play-mode tests.
- Unity only writes ProjectSettings to disk on save. Call `AssetDatabase.SaveAssets()` after changing settings.

## Commands

```bash
.venv/bin/mlagents-learn config/delivery_bot_ppo.yaml --run-id=<id>   # then press Play in Unity
.venv/bin/tensorboard --logdir results
```

## Conventions

- Unity frames: robot forward +Z, left −X, up +Y; `base_link` origin = ground point under the rear-axle centre.
